# M01 exclusions-before-persistence implementation evidence

2026-11-11, Windows 11 / RTX 4080 Super, existing Python 3.14.10 environment; base: M01 base
(branch `review-plan`). One implementer delivered M01.1-M01.3 in one implementation phase.
No source ranking, health counter, recovery, tracker identity,
speech, planner or retrieval work was done. No dependency was added; no user history, keyfile or
window content was read. All stores were disposable encrypted databases.

## Acceptance and remaining evidence

Every row has a behavior test with the writer spy (`tests/sink_spy.py`): it observes every SQL
statement that writes (including writes later rolled back), every encrypted file written through
`MediaStore.write`, every log record and the final content of every table, with a synthetic
sentinel planted in titles, URLs, channels, text and process names. Every row also has a negative
control that puts the old behavior back at its narrowest point and must then leak.

## Native evidence and unavailable evidence

Content-free outcomes: [native-m01.json](2026-11-11-m01/native-m01.json). Only windows the test
created were examined (the real window source is wrapped so every other window looks absent);
browser checks used throwaway profiles with synthetic pages.

* **Monitors:** 3, effective DPI 96 and 120, one at negative x. A synthetic password-field window
  spanning all three monitors (it is the topmost window at the other monitors' centres): while
  focused, `excluded:password_field` once and `duplicate_window` for the other monitors, no new
  frame or file; the same window is stored while it does not have the focus (the password check
  is for the focused window), as designed. A plain window on the negative-x monitor was stored; a
  window titled "Bitwarden" was excluded whether focused or not, and its title is in no sink. The test needed a short settle after focus changes: UI Automation focus follows the
  foreground window a moment later, which is the non-atomic read the guide already warns about.
* **UI Automation:** real `focused_is_password` returned True for an ES_PASSWORD edit, False for
  a plain edit and for a window without a focusable child. A real failure could not be injected.
* **Hosted app:** a new Calculator window was owned by `applicationframehost.exe` and now resolves
  to `calculatorapp.exe`. The Calculator background process is left to Windows.
* **Audio:** 6 active render endpoints enumerated; the call returned a set (not `None`); a forced
  `COMError` from the enumerator returned `None`. Audible process names are not recorded.
* **Chrome 157 / Edge, synthetic pages:** normal windows and pages titled Bitwarden or Incognito
  are kept (omnibox readable); Edge private window title `Page - [InPrivate] - Microsoft Edge`;
  **Chrome private window title carries no marker** (`Page - Google Chrome`), the marker exists only

At the M01 base, #16-#20, #24, #26 and #28 and the #25 title fallbacks were reproduced as strict xfails (marker removed only once the intended behaviour held), `.bnpparibas` with the old pattern, #27 by reading `check_url` (own UI excluded by tab title only), and #148 as strict xfails (video titles dropped).

## Accepted points

* Windows does not say which tab publishes a media session. A background tab of a browser window
  that is neither focused nor examined recently has no verdict (accepted gap, narrowed above).
* The conservative stale/unknown rule can split one video into several rows when the screen loop
  stalls; M05 owns row identity and M07A owns screen-loop recovery.
* A page can fake nothing that is read from the omnibox, but a hostile Firefox page with the
  `urlbar-input` id is not excluded by structure (Firefox path unchanged, not validated natively).
* Audible processes whose names cannot be resolved are not named; a source list is still a
  correlation, not proof of which process produced a word.
* Edge/Chrome version-specific title and caption formats can change; the native test records them.

## Gaps

* **#18:** no real playing browser tab was run through Windows media sessions end to end; next native pass / M05 (2026-11-11).
* **#148:** Firefox, Zen and Brave private-window layouts were not validated natively (Zen is the primary browser); next native pass (2026-11-11).
