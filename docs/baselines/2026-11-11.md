# Local baseline 2026-11-11

Measured on this PC at the 2026-11-11 baseline revision, before the audit's production fixes. This replaces
the previous baseline and raw results from another device; those numbers are not a comparison
point. They are not kept in this repository. No application, fixture or scorer was changed.

## Scope and reproducibility

Machine: AMD Ryzen 7 7800X3D 8-Core Processor, 8 cores / 16
threads; 31.74 GiB RAM reported by Windows;
NVIDIA GeForce RTX 4080 SUPER (16376 MiB VRAM, driver 621.01). Microsoft Windows 11 Pro build 26200, Python 3.14.10,
numpy 2.5.4. Timezone: Europe/Paris.

The [environment record](2026-11-11/environment.json) contains exact package versions, source and
artifact hashes, runtime build output, the guard wrapper and result checksums. Models matched
their pinned sizes and SHA-256: Gemma 4 12B QAT Q4 and Qwen3-Embedding 0.6B Q8; runtime b12209.
Only those public model/runtime folders were staged from installed assets. No history database,
keyfile, captured media or user configuration was opened. Fixtures use disposable encrypted stores.

The same four measurement stages were run sequentially with the existing environment and no
development resource limits. Python evaluation entrypoints ran with the unchanged test external-
socket guard and offline flags; llama-server used its production offline/loopback configuration.
The first restricted CPU attempt failed in sandbox temp setup and produced no measurements;
the completed native run used a workspace temporary directory. Desktop load was not controlled.

```powershell
.venv\Scripts\python.exe -m pytest -q --basetemp=.test-tmp/<fresh-name> -rx
.venv\Scripts\python.exe scripts/eval_planner.py --output planner.json
.venv\Scripts\python.exe scripts/bench_baseline.py --rows 100000 --episodes 40000 --segments 20000 --visits 50000 --repeats 5 --seed 0 --output bench-100k.json
.venv\Scripts\python.exe scripts/eval_ask.py gemma-4-12b-qat-q4 --models-max 2 --repeats 3 --split all --data-dir <separate-model-runtime-folder> --output ask-gemma.json
```

For evaluation scripts, install the recorded guard wrapper before the entrypoint and direct
TEMP/TMP to a workspace scratch directory. No legacy-scoring model run was repeated: the
corrected production-path evaluation is the baseline.

## Remaining boundaries and defect notes

No hardware self-test, real speech, natural capture, total RAM/VRAM attribution or clean-machine
packaging validation was performed. Synthetic coverage is not daily-use accuracy. The speech
fixtures and study results are in `eval/transcript-hallucination-rejection/` and
`eval/segment-speaker-attribution/`; the method-study data and rerun instructions are in
[eval/README.md](../../eval/README.md). Real speech accuracy still needs corrected references and
speaker labels. The STT comparison-panel evaluation gaps (#117, #119-#122) and public speech
fixture promotion remain open.

The baseline's unnumbered defect notes remain: game overlap can be missed during the tail of an
earlier longer app visit or conversation; the banking-host rule has a `.bnpparibas` gap; video
soundtrack lines can lack their episode link. The two query bounds have strict xfails; the latter
two are not pinned.

The incoming study-data branch also retained `2026-11-11/ask-gemma.log.txt` and
`2026-11-11/ask-gemma-old-scorer.log.txt` from the earlier baseline. They are historical evidence,
not logs of the local measurements reported above.
