Every mismatch is the known class: on fuzz 0..9999 all 265 differing mic segments are > 300 s
and have d = 0 to both the oracle's cluster and C3's (later) cluster, i.e. the mic spans a whole
voice gap and the tie-to-earlier rule is lost because sigma > S_k. Replay stays consistent
(0/1000) even then, because the assignment is deterministic per input.

Why <= 300 s is exact (matches the refuter): S is strictly increasing (vs_{k+1} > ve_k + 300 s).
Attachable <=> d < 30 s, so the argmin of d is attachable iff any cluster is, and one overlap
check suffices. Pairwise k vs k+1: unclamped d_k < d_{k+1} <=> sigma < S_k; equality -> k.
Clamping only breaks it when d_k = d_{k+1} = 0, which needs m.start <= ve_k and
m.end >= vs_{k+1}, i.e. length >= 300,001 ms. Non-adjacent clusters are strictly farther.

FAILS WHEN: a non-voice mic segment > 300 s spans an entire >300 s voice gap (goes to the later
cluster instead of the earlier). Capture caps mic segments at 30 s (src/akashic/capture/audio.py:79,
per the candidate brief; not re-read here). If that cap is ever lifted, a cheap fix is: after
bisect, if j > 0 and m.start <= ve[j-1] (d = 0 to j-1 too), take j-1 (and walk left while true). Untested here.

Assumes rows arrive sorted by (start_ms, id) (the SQL ORDER BY); members are emitted in row order.
