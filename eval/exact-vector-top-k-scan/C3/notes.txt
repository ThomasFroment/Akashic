Fix rounds (check that failed, and the fix)
- Round 0 (as specified, copyto conversion, sets, rows kept until the next fetch): 100k quick
  run after_fetch 540-690 ns/row (min of 7) -> over budget.
- Round 1: (a) free each chunk before the next fetchmany (chunk step in a helper); (b) bit-shift
  float16 -> float32 (sign-extend int16 -> int32, << 13, & 0x8FFFFFFF = value * 2**-112 exactly,
  subnormals included) scored against query * 2**112 (exact while |q| < 2**15, finite, float32
  1-D query); chunks with any inf/NaN half (two int16/uint16 max reductions, ~7 ns/row) and
  other queries use numpy's cast; (c) itemgetter column maps instead of zip(*rows).
  Full run (round1/): all passed except embeddings/segment_only60_excl20 at 1m = 523 ns/row
  (set membership on a 360k-id set: cache misses).
- Round 2: only/exclude -> one bool table indexed by owner id (only minus exclude), built from
  np.array(list(ids)) once per call when ids are ints in [0, 2**24); else today's sets. That
  scenario dropped to 321 (floor_check) / 431 (final harness run). Final run passes all checks.
  (Brief allowed one fix round; round 2 is a second, small one, stated here.)
