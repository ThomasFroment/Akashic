Fixes found while building (beyond the candidate block):
  - game pointer with s = +inf at the sentinel: advancing unconditionally ran past the end
    (IndexError on "real" fuzz cases); the advance loop is now bounded by G.
  - URL: a strict ">" scan equals today's stable reverse sort only when durations are totally
    ordered. A NaN duration (s = e = +-inf) is always alone in its run when rows are in start
    order, but with unsorted rows it can sit inside a run; C2 detects a NaN process sum and
    recomputes the URL exactly as today. Without that fallback: 280/5000 mismatches on
    shuffled rows with +-inf visits; with it: 0. Shuffled-row fuzz (10k cases, games): 0.
  - exception-based dict updates (try/except KeyError) were slower on the fragmented shape
    (many misses); dict.get is used.
Contract caveat: rows are unpacked as exactly 6 columns (the SQL's select list); today only
indexes r[0..5]. Rows of another width would raise in C2 but not today.
