## Notes (hand-written, 2026-11-20)

- Verdict: C2's headless result holds on real WGC captures. <= 11 device px at scale 1.0: 0.005-0.007
  (Chrome, Edge) and 0.002 (Zen) against 0.53 today; 4K <= 11 px 0.003 against 0.044. Every other
  bucket <= 0.003. Headless study: 0.006 / 0.004.
- ClearType is present on real captures: 95-98 % of small page strips carry fringes (median energy
  0.39-0.40, the same as headless 0.31-0.43). The only grayscale page strips are <= 20 px wide
  glyph fragments on light pages (bullets, rules), not text lines. The ink-pixel share (the corpus'
  `fringe_share_of_ink` metric) is 0.65-0.85 against 0.81-0.85 headless; lower on light Edge/Zen pages.
- Grayscale surfaces: the browser UI (tab titles, toolbar labels, Zen's sidebar) is grayscale-AA:
  0-9 % of small UI strips fringed (the Chromium omnibox URL text is ClearType). C2 reads those with
  luma Lanczos, as designed.
- The RGB/BGR vote chose RGB on all 320 calls; the system setting is FontSmoothingType 2 (ClearType),
  FontSmoothingOrientation 1 (RGB).
- Cost on real windows is higher than on the corpus because the browser toolbar adds words to every
  call: TIMING pages p95 +17 to +91 ms per set (+50 overall) against the +50 ms budget; CPU 1.27-1.68x
  (1.44x overall) against 2x. One call per page over all pages: CPU 1.42-1.78x, p95 +45 to +98 ms.
  Another agent was using the right monitor during the run, so wall-time percentiles carry noise;
  CPU ratios are steadier.
- Chrome/Edge windows were topmost but not always the foreground window (`all_foreground` false);
  Zen windows were foreground. CER shows every frame was fully painted.
- Not covered: real apps other than browsers, busy backgrounds, OLED/grayscale-only setups, game-mode
  deferred reads (WebP).
