Goals: (1) cut screen-text error for small fonts and on 1440p monitors; (2) [resolved by the harness: the residual 1440p error at large sizes is a scorer line-wrap artefact, not WebP; score M3.1 wrap-tolerant]; (3) keep OCR CPU and latency within budget.
Fidelity: must: harness M3.1 CER at <= 11 device px at most 0.05 and 1440p CER at most 0.10 on the standard and day runs; must: 4K and UIA CER no worse than today; must: M3.3 unique-text recall no lower than today. may fake: text under 8 device px stays unreadable; may fake: OCR reading order and layout as today; may fake: game-mode deferred OCR keeps its 60 s cadence.

Harness findings (step 1, harness/ in this folder; numbers only):
- Goal 2 resolved as a scorer artefact: eval/quality/score.py matches each truth line against single OCR lines, and the harness pages wrap long lines (mixed sentences 132-270 chars), so wrapped halves never match. With a wrap-tolerant match, today's stored text at 1440p drops from 0.371 to 0.201, and rows >= 16 device px from 0.27 to 0.02 (standard) / 0.215 to 0.013 (day). This study scores M3.1 wrap-tolerant ("join" metrics); the scorer fix is a harness item.
- The lossy WebP copy barely matters: only game-mode windows are OCR'd from it (screen_writer.py:356-359); baseline OCR on decoded WebP frames vs the stored live text: 1440p 0.452 vs 0.456, 0.41 vs 0.41; 4K 0.095 vs 0.097. A codec spike on synthetic text found <= 0.01 CER difference at >= 11 px between raw, WebP q50-q100, lossless and JPEG.
- Real Chromium text (headless Edge, ClearType subpixel AA on 81-85 % of ink pixels) is harder than Pillow text: 1440p CER by CSS px today 9: 0.82, 10: 0.80, 11: 0.19, 12: 0.07, 13: 0.01, 14+: <= 0.006; 4K 9 px 0.08. Grayscale AA (--disable-lcd-text) is slightly worse than ClearType at 11 px (0.25 vs 0.19).
- Fixed 3x Lanczos for everything (explored/up3x_lanczos): 1440p 9 px 0.26, 10 px 0.05, 11 px 0.009; but CPU 4.5x per live call and 3.8x per deferred window (limit 2x), p95 +330 ms live (limit +50 ms); real dense windows 0.75-1.5 s per call. On the real runs' lossy frames it takes <= 11 px 1440p from 0.67/0.64 (stored) to 0.049/0.058 (wrap-tolerant).
- Today's live OCR: find_text_box crop then WindowsOcr.recognize at native size; p50 63 ms / p95 98 ms on sparse 1400x720 pages, 250-415 ms on dense real windows.

Mechanisms:
M1 Uniform Lanczos upscale before RecognizeAsync: s = 2-3x, Lanczos > bicubic > bilinear, 4x no better; cost grows with pixel count of the whole crop [docs/research/windows-ocr-small-text-upscaling.md; harness explored/up3x_lanczos]
M2 Adaptive scale to a target text height (Text-Grab: average word height from a first 1x pass, scale = 40 / height, default 4x when no words, capped by MaxImageDimension, no lower clamp) · costs a first OCR pass · breaks with mixed sizes in one window [Text-Grab, via the research report]
M3 Per-line or per-block crops scaled independently · 1+N OCR calls unless boxes are free; risks p95 [Text-Grab rule; hypothesis]
M4 Pad + edge-colour fill (PowerToys: min 64 px + 8 px margin, fill with pixel (0,0), fixed 1.5x HighQualityBicubic) · matters only for small crops [PowerToys BitmapPreprocessor.cs:13-66]
M5 Chroma removal (luma or max channel) to kill ClearType fringes · hypothesis; flat contrast for coloured text on similar-luma background [opinion only]
M6 Binarization (Otsu/Sauvola) · discards AA information that upscaling exploits; Sauvola costly [Tesseract docs]
M7 Text-region detection by gradient density (Akashic find_text_box: 16x16 cells on a half-size frame, horizontal gradient > 48, density 0.02-0.5; screenpipe Otsu text regions) · gives where text is, can drive selective upscaling [src/akashic/capture/imaging.py:77-105; screenpipe text_regions.rs]
M8 Text-height estimation without OCR: row profiles of edge density inside a text box (stroke-height / x-height estimate from horizontal projection), or connected-component heights · cheap numpy; breaks on mixed sizes and icons [standard document-analysis technique]
M9 OCR result confidence/word boxes from Windows OCR (OcrLine/OcrWord bounding rects; no confidence score exposed) · word heights from a native pass give the scale for a second pass on small regions only [Windows.Media.Ocr API]
M10 Lossless crop storage (WebP lossless q50 m2: 10 KB vs 42 KB lossy on a 640x640 text crop; whole noisy page 553 vs 361 KB) · only needed if deferred OCR mattered; it does not for normal windows [codec spike]
M11 OCR before encoding (live path already reads raw pixels; only game-mode windows are deferred on WebP) [screen_writer.py:356-359]
M12 Downscale avoidance: recognize() thumbnails images above MaxImageDimension (10000 on the target PC) [platform/win/ocr.py:49-52]
