Design as built
  frames.text_key = HMAC-SHA256(ctx.hmac_key, utf-8 text)[:16], written in the same statement as the
  text (insert_frame, set_text), nulled with it (expire_frame_text). text_passages WITHOUT ROWID,
  PK(text_key, model, start_char). frame_vec_horizon(cutoff_ms, done_ms): single row, absent = no cutoff.
  Triggers: AFTER DELETE / AFTER UPDATE OF text_key delete a key's passages when NOT EXISTS a frame with
  that key at ts >= horizon (index seek). Guard triggers (installed after backfill) abort writes where
  text and text_key disagree. Indexes: frames_key_ts(text_key, ts_ms, window_title, url);
  frames_ts widened to (ts_ms, text_key) so window->keys is index-only.
  embed_pending: one representative frame per missing key (ts >= horizon), publish checks a frame with the
  key still exists at/after the horizon. expire_embeddings: raises the horizon first (old frames leave
  vector search in that same transaction), then deletes passages of keys with no frame >= horizon, in
  batches of 500 keys, scanning only [last completed cutoff, cutoff).
  Query: FTS per frame (unchanged SQL + key/title/url), vectors per key over keys with a frame in
  [max(start, horizon), end); both collapsed to groups (text_key, title, url), RRF on groups; slots = runs
  (gap > 15 min), R = 2 per group, runs adjacent under the group score, within a group best-FTS-frame
  first then recency; rep = best-bm25 frame of the run else its latest; extra = {snippet, first_ts,
  last_ts, count}. Textless (expired) frames stay one group per frame.

Failures / caveats
  - Write p99 budget borderline (see above); p50/mean/p90 well inside.
  - top1_agree 34/36: the top group differs from today in 2 queries (group-level RRF compresses ranks of
    identical frames; not investigated further, groups_ok is 36/36).
  - Runs of one group take adjacent slots (spec), so a 2-sighting group pushes one other group out of the
    5 slots; harness groups_ok unaffected (no fixture group has 2 runs in a window).
  - FTS depth 200 still counts frames: a long run of identical frames can use most of the FTS candidate
    list (diversity of FTS candidates unchanged from today; vector side is per key).
  - Upgrade cannot infer today's vector-retention cutoff: upgrade_from_today(ctx, vec_cutoff_ms) takes it;
    without it, old frames sharing a key with a newer frame become semantically reachable again.
  - text_key is tied to ctx.hmac_key: rotating the data key needs a re-key of frames + text_passages.
  - Textless (expired) frames are not collapsed (title/url-only FTS hits, one group per frame).
