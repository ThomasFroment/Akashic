C1 Three-layer priority partition: confirmation-bounded hold + back-dated keyboard/mouse away (decompose-D1, exploit-E1 without its audio veto)
  USES: M3, M16, M7, M12 (optional exact lock edges)
  DERIVATION: app(t) = focused process at t if recording(t) and present(t). Focus is in the desk signature, so a focus change stores a frame after the 0.3 s debounce (normal capture mode; game mode keeps today's handling); between frames the band holds to the next session start; after the last frame, every unchanged check proves the same focus, so end <= the monitor run's checked_ms + delta (5 s focused, 15 s others); recording(t) = no stored gap (sleep stored as all/stalled); present(t) ~ keyboard/mouse idle < T: capture stores an away span [last_input, return) back-dated once idle >= T, with idle = (GetTickCount - dwTime) mod 2^32 (wrap-safe), clipped to >= the end of the last stalled gap (stale value after wake). Band = [start, min(next start, checked_ms + delta, gap start, away start, game end, end of recording)). Priority gap > away > app; away is a typed span, not a hole. Lookups by bisect, no per-band SQL.
  COST: capture: GetLastInputInfo + GetTickCount on the existing 1 s gap tick ~5 us; <= 20 away rows/h x ~40 B ~0.8 KB/h. Query per 16 h day: ~3.2k sessions + ~100 gaps/away rows + ~100 monitor runs, fetch ~7 ms + linear merge ~17 ms ~24 ms vs 50 ms/day.
  FIDELITY: keeps holes <= 5 % (M3 measured 0.5 % on smoke), overlap <= today (clipped at the next start), never into a gap or past the end of recording, no time across lock/sleep/pause/stop/away. Fakes: band end up to delta late; away from keyboard/mouse only.
  FAILS WHEN: a video, a silent read or gamepad play longer than T with no keyboard/mouse input is cut as away (undercount; M5.3 may come out worse than today where today's playing video kept storing frames); a SendInput jiggler means away never fires; the monitor run leaves "shown" during a long read (confirmation stops, untyped hole).
  TEST: old stores have no idle record: replay the hold part on the five runs; synthetic scenarios for idle > T, lock, sleep, 10-60 min static page; M5.1 <= 5 %, M5.2 <= today, M5.3 < today on every run, 0 band-seconds in gaps or after the end of recording; ms/day median of 9.

C2 C1 + presence by closing with a same-process audio veto (transplant-T2 merged with exploit-E1's veto)
  USES: C1 (M3, M16, M7), M8 (restricted), M17 (stored as runs)
  DERIVATION: store input-activity runs (a run grows while inputs are < 30 s apart, lossless for T >= 30 s) and audible runs of processes (M17 merged within 5 s, kept durable); present = closing C_T(input runs) ∪ audible runs whose process equals the band's process, an audible run holding presence at most 3 h past the last input; app band' = band ∩ present minus stored gaps; the cut becomes a typed away band. Same-process matching makes the Wave Link mixer (never focused) unable to veto; music in a background app cannot veto.
  COST: capture ~3 us/tick + enqueue; input runs typ. 0.5 KB/h (worst 3 KB/h) + audible runs <= 1.5 KB/h. Query ~18-28 ms/day.
  FIDELITY: C1's musts; keeps video watched without input in its focused, audible player. Fakes: presence during silent input-free use.
  FAILS WHEN: a focused autoplay playlist or stream left playing after the user leaves counts up to 3 h; a silent static read longer than T is cut; Steam Input or a jiggler never away.
  TEST: C1's tests plus synthetic focused video without input (no away), focused music with a static screen after leaving (counted <= 3 h), background music with the user away (away from last input +- 1 s).

C3 Foreground switch rows as exact band edges (decompose-D3, transplant-T1, exploit-E2 merged)
  USES: M4, M6, M3 (fallback inside hook-down spans), M16, M7 (away from C1)
  DERIVATION: the existing EVENT_SYSTEM_FOREGROUND hook stores one row per foreground process change (wall ms stamped in the callback or wall_at_drain - (mono_at_drain - event_mono), interned process id; NULL process for an excluded window or the ApplicationFrameHost before the child attaches, resolved from the next frame; A-B-A flicker < 0.3 s collapsed). Edges = switch rows ∪ process-changing session starts (a dropped event costs <= 0.3 s outside game mode). Band = [edge_k, edge_k+1) minus gaps, away (C1), game end, end of recording; identity (title/URL) and sub-edges from frames inside the band. A healthy hook with no event proves no switch, so a static read needs no monitor confirmation; hook-down spans are stored and fall back to M3. Rule 2 holds: only "a switch at t" is stored for excluded windows.
  COST: capture per event ~1 us + pid cache (miss ~30-40 us once per pid), <= 0.15-0.6 ms per burst vs 1 ms/tick; storage ~15-24 B/row: 60-100 switches/h ~1.1-2.2 KB/h, 300/h ~5-7 KB/h. Query ~34-38 ms/day (needs a hwnd or process-change index; no full frame join).
  FIDELITY: C1's musts; exact process edges, including in game mode (better than today); no hole when a monitor run is not shown. Fakes: title/URL boundaries at frame times; away as C1.
  FAILS WHEN: hook down (M3 quality inside); UWP host or elevated window (process unknown until a frame); virtual-desktop switch without a FOREGROUND event (unverified; bounded by frame latency, up to 15 s in game mode); UAC secure desktop invisible to the hook (previous app extends through the prompt); focus on the desktop or taskbar becomes an "explorer" band; walk away unlocked (needs C1's away).
  TEST: needs new runs with switch rows; on old runs, simulate the switch rows from the observer's truth/os.jsonl fg events (what a hook would see); edge error vs truth (median <= 0.3 s, max <= delta); 10 % dropped rows -> M5.3 change <= 0.01; storage KB/h from the day run's switch rate.

C4 Presence split by channel (decompose-D2)
  USES: M7, M10, M17, M8 (restricted), M16, M3
  DERIVATION: present(t) = OR over channels c of [t - last_c(t) < T_c]: K keyboard/mouse (M7), P XInput pad (M10, dwPacketNumber changes), V focused process audible AND its monitor stored a frame in the last 15 s (picture changing), S the user's own stored mic speech (voice-app case); away = AND of quiet spans, start = max over channels of last activity; V alone holds presence at most 3 h past the last K/P/S activity; same band clip as C1.
  COST: capture ~10 us to 0.5 ms per tick (P dropped if an empty-slot probe exceeds 0.5 ms); <= 100 rows/h x 40 B ~4 KB/h; query ~30 ms/day.
  FIDELITY: C1's musts; keeps passive video with motion, XInput pad play, voice calls with speech. Fakes: non-XInput pads (DualSense, Switch, DirectInput invisible), silent watching.
  FAILS WHEN: autoplay/looping stream after leaving (up to 3 h over-count); XInput stick drift (never away); DualSense play without audio and motion (undercount); S arrives only after transcription (live days miss it).
  TEST: C1's tests plus scripted passive video > T, music with static screen > T, pad-only play > T, voice call without input; music static -> away from last input +- 1 s; passive video -> no away; worst tick cost <= 1 ms over 1 h.

C5 Display-request back-dating instead of an audio veto (exploit-E3)
  USES: M7, M9, M11, M3, M16, M6
  DERIVATION: away iff idle >= T and now - last_req_ms >= T, where last_req_ms is the last tick at which the aggregate CallNtPowerInformation(SystemExecutionState) ES_DISPLAY_REQUIRED bit was set; away start = max(last_input, last_req_ms); optional hard edge from GUID_SESSION_USER_PRESENCE "not present" (callback registration, no window), back-dated the same way. Drops the audio heuristic (no mixer or music false vetoes).
  COST: ~6 us per tick; storage ~0.05 KB/h; query as C1 ~28 ms/day.
  FIDELITY: C1's musts. Fakes: away = input plus declared display requests.
  FAILS WHEN: the aggregate bit does not reflect PowerCreateRequest requests (unverified: then video without input is cut); a stuck request (WebRTC tab, OBS) means away never fires; a voice call without input and without a request is cut; controller play in a game without requests is cut.
  TEST: spike first: video in Edge/Chrome and a local player with no input, log the bit at 1 s, pass >= 99 % of playback set; then C1's tests plus video-without-input app time kept >= 95 %.

C6 Per-app idle threshold by Otsu split (transplant-T3)
  USES: M7, C2's input-run record, M3, M16, M8
  DERIVATION: per focused process, T_p = Otsu threshold of the log2 input-gap histogram over the previous 30 days (64 bins, 32 s-68 min), accepted only if separability >= 0.6 and n >= 50 gaps, clamped to [120 s, 20 min], else 300 s; frozen per day for deterministic re-derivation; then C2's closing with T = T_p(band process).
  COST: query ~25 ms/day (cached per-day histograms ~5 KB/day); backfill 30 days ~0.6 s; capture as C2.
  FIDELITY: C2's musts; fewer false-away cuts on read-heavy apps. Fakes: apps with < 50 gaps and the first 30 days (fixed 300 s).
  FAILS WHEN: an app used mostly passively has unimodal long gaps -> T_p at the 20 min clamp (up to 20 min of absence counted); behaviour change misclassified for up to 30 days.
  TEST: as C2 plus a synthetic 30-day two-lognormal mixture per app: |T_p - T_ref| within one bin, classification error <= Bayes + 1 %.
