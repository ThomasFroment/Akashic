Problem: decide when a captured screen frame changed enough to store, so a one-word chat reply, a notification badge or a short line of small text is kept while a blinking caret, a cursor and a seconds clock are not.
Goals: (1) keep every meaningful small change (a one-word chat reply at 13-16 CSS px, a 16 px badge, a short line of small text) on both 4K (125 %) and 1440p (100 %) monitors; (2) store no more useless frames than today (caret blink, seconds clock, spinner); (3) the OCR gate uses the same test, so a kept frame's text is re-read.
Fidelity: must: catch a one-word reply and a badge in every sub-pixel placement at 1440p and 4K, both themes; must: never fire on a 1-2 px caret blink; must: harness M1.1 focused recall at or above today and M1.2 useless ratio no worse than today + 0.05. may fake: count any text-shaped change as meaningful (a seconds timer stores a frame each check); may fake: miss changes in fonts under 9 device px; may fake: keep today's behaviour during game mode.
Budget: <= 3 ms extra CPU per 4K compare on one core of a Ryzen 7 7800X3D (today about 1.5-1.9 ms compare + 6.7 ms signature), a few MB extra memory per window, numpy and Pillow only (no new dependency; ctypes/comtypes/winrt already in the project), no GPU model per frame.
Non-goals: game-mode capture intervals, OCR accuracy itself, cursor capture (off today), video/animation handling beyond today, retention or later frame thinning, Windows builds without the APIs in use.
Explored: per-tile changed-pixel count >= 6 (refuted: a 4K/125 % caret moves 6-12 reduced pixels, a 13 px "ok" as few as 9); per-16x16-tile span >= 3x3 over two offset grids (missed a word in 10-80 of 4096 placements); per-tile span >= 3x3 over four grids (0/4096 missed, caret 0/4096, 2.2-2.6 ms per 4K compare, synthetic Pillow text only, unmeasured on real screens; seconds timers and spinners fire it); WGC dirty regions (report what the app redrew, a whole 502x32 label for a one-word change and a 4x24 rect for a caret, Windows 11 24H2+ only).

Mechanisms:
M1 Global changed fraction (Akashic today): signature = blake2b of the frame reduced 4x to gray; differs = equal digest -> False, else > 1e-4 of reduced pixels moved > 16 levels · assumes a meaningful change is large · breaks when the change is one word (missed 40/40 synthetic small changes) [src/akashic/capture/imaging.py:26-62]
M2 Exact tile compare (TigerVNC 64x64, FreeRDP 16x16, WebRTC differ_block): memcmp per row, first-mismatch exit, bbox trim of changed tiles, no thresholds, no history · assumes every pixel change matters · breaks when a caret, cursor or 1 px noise must be ignored (fires on all) [TigerVNC ComparingUpdateTracker.cxx; FreeRDP shadow_capture.c; WebRTC differ_block.cc]
M3 Per-tile span test over offset grids: in some 16x16 tile of the 1/4 gray difference mask (> 16 levels), moved pixels span >= 3 columns and >= 3 rows; grids offset (0,0),(0,8),(8,0),(8,8) · assumes words and badges are >= 3x3 reduced px and a caret is 1-2 wide in every placement (measured on synthetic frames) · breaks when a nuisance is text-shaped (seconds clock, spinner), when sparse moved pixels 3 apart pass a bbox test (add a min count or closing), on unmeasured ClearType/real content [docs/research/screen-change-detection-small-text.md; eval/quality/spikes/change_detection_small.py]
M4 Densest-window count (pixelmatch windowSize): max over NxN sliding windows of the diff-mask count, via column sums · assumes local density separates meaningful change from scattered noise · breaks when a caret's count equals a small word's (counts overlap at 4K: caret 6-12, word 9-28) [mapbox/pixelmatch index.js]
M5 Block SAD hi/lo/frac (FFmpeg mpdecimate): SAD of 8x8 blocks (stride 4); differs iff any block > hi (768) or more than frac (0.33) of blocks > lo (320) · assumes change magnitude marks meaning · breaks when a high-contrast caret matches a word in SAD; useful only as a cheap prefilter (~0.3-1 ms est. at 1/4) [libavfilter/vf_mpdecimate.c]
M6 Minimum-shape connected component (Stauffer-Grimson): drop foreground components of 1-2 pixels; use shape (width AND height >= 3) not area for thin nuisances · assumes noise is isolated or thin · breaks when the nuisance is wide (block cursor, Text cursor indicator) or a meaningful change is 1-2 px wide (a lone "l" or "I") [Stauffer & Grimson CVPR 1999]
M7 Per-tile state set for toggles (Stauffer-Grimson multi-modal, adapted): per changed tile keep K=2-3 recent content hashes (CRC32 of the 16x16 gray tile, ~4 us for 8 tiles); a new hash already in the set = A-B-A toggle, not stored · assumes a blink toggles between exact states · breaks when pixels drift (sub-pixel AA), on a seconds clock (60 states), and it hides a genuine revert to earlier content; must be small and recency-limited [Stauffer & Grimson 1999; measured CRC cost in researcher spike]
M8 Persistence re-check: when a check fires, re-grab ~0.3-0.6 s later (jittered; caret blink default 530 ms, GetCaretBlinkTime) and store only if the tile content is the same, or store and drop if the next check shows the tile back to the reference · assumes a meaningful change lasts >= one re-check and a blink does not · breaks when content vanishes fast (a 2 s toast) or the re-check phase aligns with the blink period [design from researchers; GetCaretBlinkTime docs]
M9 Two-reference compare (t-1 and t-2): a change that matches the t-2 state is a toggle · assumes the blink returns to an earlier exact state · breaks with sub-pixel drift; costs one more 1/4 gray frame (~0.5 MB at 4K) per window [researcher lead]
M10 Caret rectangle hint, veto only: GetGUIThreadInfo (rcCaret, GUI_CARETBLINKING = currently visible; system carets only, one user32 call) and MSAA AccessibleObjectFromWindow(OBJID_CARET).accLocation (Chromium's AXSystemCaretWin, only when Chromium accessibility is on; Firefox only when accessibility is active); mask changed pixels inside the caret rect + 1-2 px; a hint can only remove a blink, never add a change · assumes the app exposes its caret · breaks when the app draws its own caret (Terminal, games, Chromium with accessibility off); cross-process WM_GETOBJECT can block on a hung window [learn.microsoft.com GUITHREADINFO, GetCaretBlinkTime; Chromium ax_system_caret_win.cc; Raymond Chen 2026-01-08; Mozilla bug 1504963]
M11 Gradient-density text cells (Akashic find_text_box): 16x16 cells on a half-size frame, horizontal gradient > 48, text iff density in [0.02, 0.5] · assumes text = dense horizontal gradients · breaks when small text is smoothed by downscaling, any busy region qualifies; ~1-2 ms est. at 4K [src/akashic/capture/imaging.py]
M12 Anti-aliasing pixel rejection (pixelmatch / Vysniauskas 2009): drop a differing pixel if it is an AA pixel (neighbour-difference sign pattern, min/max siblings) in either image · assumes sub-pixel re-rendering of the same glyph · breaks on a 1-2 px caret (not AA, still counted), noise; full-res per-pixel cost far over budget in numpy [pixelmatch README; Vysniauskas, Elektronika ir Elektrotechnika 7(95) 2009]
M13 Sparse fast path: array_equal early exit (0.02 ms), mask via |a-b| > 16 (0.47 ms at 960x540), count_nonzero, then only the nonzero coordinates binned per tile over 4 grids with per-tile bbox extent: 0.40 / 1.14 / 1.42 ms (identical / word / caret) vs dense 4-grid 2.46 ms (researcher's machine, not the 7800X3D) · assumes few changed pixels · breaks when a large area changes (fall back to dense or to M1's fraction, already "changed") [researcher timing script]
M14 Reduction dilutes thin marks: averaging 4x4 makes a 1 px caret a 1-wide low-contrast column; a word survives as >= 3x3 · the reduction factor and the delta threshold set the caret/word separation [docs/research/screen-change-detection-small-text.md]
